# 自动启动与升级入口

本板 KEY2 是 PC4，外部10k上拉、按下接地（原理图V1.2.6第6页），低电平有效。不能沿用旧key驱动的高有效假设。

## 使用

- 正常上电：App有效时等待约1秒维护窗口，随后校验并启动天气时钟。
- 上电/复位维护：先按住KEY2，再上电或按复位。识别后一直留在升级模式，不需要一直按住；松开后再操作。
- 运行中维护：天气时钟长按KEY2约2秒，写入一次性升级请求，软件复位后Bootloader留在升级模式。串口输出READY，PB0指示灯点亮。
- 电脑端维护：在正常启动的约1秒窗口内发送`?`、`u`或`g`，命令不会被吞掉。已运行的天气时钟不监听升级串口命令，先用长按入口进入。
- 退出维护：在未破坏有效App时发送`g`，或松开KEY2后复位。若已开始擦写导致App无效，只能重新完整升级，g会报告具体检查错误。
- App无效：不自动跳转，一直保留升级入口。升级完成后仍由发送器的`--boot`发送g启动；没有改变DONE语义。

## 请求与按键实现

App中独立低优先级任务每20ms采样KEY2，持续按下约2秒触发。短按不触发，也不占用既有业务任务。当前仅GCC/Make工程接入了新增源文件，Keil工程需另加源文件并适配此前的链接地址。

App和Bootloader共同保留RTC BKP19R，魔数0x49504155。写入前开启PWR访问并暂时打开DBP，写入读回后复位；Bootloader启动时读取并清除。没有复位RTC备份域，不写日历寄存器；此寄存器不要分配给其他用途。请求不是固件有效标记。

## 错误信息

完整性层返回具体枚举结果及诊断数据，协议层输出ERROR前缀。旧bool接口保留用于原有调用与测试。

| 输出 | 含义 |
| --- | --- |
| ERROR header | 文本升级头接收或解析失败，尚未开始擦除 |
| ERROR erase | 擦除失败 |
| ERROR receive N | 正文接收失败，N为累计收到字节数 |
| ERROR write N | 块写入或读回失败，N为此前成功写入量 |
| ERROR length | 提交函数收到越界长度（正常协议解析会提前拒绝） |
| ERROR vector | 初始栈或复位入口非法 |
| ERROR image_crc expected=… actual=… | 固件整包CRC不符 |
| ERROR header_write field=length/crc/info_crc/magic | 描述头字段编程或读回失败 |
| ERROR header_verify | 描述头完整性检查失败，包括无有效提交 |

发送器按ERROR前缀停止，仍兼容。START检查同样使用详细错误；仅上电发现无效App时记录App invalid并留在升级模式。
